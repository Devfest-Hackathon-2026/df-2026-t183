# 第2段階のフロント連携

API の正式な契約は [API 設計](API_DESIGN.md)、保存・再送・期限は [データ設計](DATABASE_DESIGN.md) を参照する。この文書はフロント担当が接続するときの確認順序をまとめる。第3段階の削除は今回の対象外。

## 接続前の設定

- Go API は用途別の鍵を両方設定すると第2段階になり、署名・Firestore が必須になる。切り替え前に配信したフロントは、開始応答に署名と期限の両方がない場合だけ第1段階として扱い、その振り返りは保存されない。署名付きで始まった学習では、対話や保存の応答で署名や確定保存の情報が欠けていれば失敗として扱う。
- `VITE_API_BASE_URL` に API の公開オリジンを設定する。Go 側の `ALLOWED_ORIGINS` にフロントのオリジンを登録する。
- 保存前の期間案内に使う `VITE_HISTORY_TTL_DAYS` を、Go の `HISTORY_TTL_DAYS` と合わせる。初期値は30日。保存後は API の `expiresAt` を表示する。
- `SESSION_KEYS_JSON`、`HISTORY_KEYS_JSON`、Google Cloud の資格情報は Go の実行環境だけに渡す。`VITE_*`、フロントのコード、localStorage へ秘密鍵を置かない。
- レスポンスは JSON の形・型・上限を確認してから扱う。エラーや生成テキストを HTML として挿入しない。

## 画面で保持する状態

| 項目 | 扱い |
| --- | --- |
| 教材本文 | 入力上限10,000文字。開始時に送った正規化済みの同じ本文を最後まで使う |
| `sessionId` | `/api/start` の UUID。これだけでは保存や再閲覧はできない |
| `sessionProof` | サーバーの署名。解析して再生成せず、対応する本文・履歴と一組で次の要求へ渡す |
| `sessionExpiresAt` | 開始から2時間の固定期限。対話・再読み込みで延ばさない |
| `history` | 最初は開始応答の `model` 1件。継続成功時に `user` と `model` を一緒に追加する |
| 入力下書き・自己確認 | 確定履歴とは分ける。未送信の下書きは保存対象に含めない |
| 終了要求の凍結状態 | `/api/summary` を送る直前に固定し、成功確認まで変更しない |
| 振り返り・閲覧キー | 保存成功後のメモリ表示だけ。localStorage や URL に書き込まない |

localStorage は未完了の学習1件に限り、版・期限・型・上限を検証して復元する。開始前の教材下書きにも最長2時間の固定期限を持たせる。利用者が確認して回答欄へ取り込んだ認識文字は、回答下書きとしてこの一時保存に含む。保存成功・明示破棄・期限切れで取り除き、ブラウザが閉じていた場合は次回起動時に期限を確認する。読み書きが使えない場合は復元不可を案内し、画面内の学習を落とさない。共有端末の同じブラウザでは他の利用者が読めることも開始前に伝える。音声と未確認の文字起こしは [音声 API の契約](SPEECH_TRANSCRIPTION_API.md) に従って永続領域に置かない。

## 接続順序

1. `POST /api/start` に `{ learningContent }` を送る。成功の `sessionId`、`sessionProof`、`sessionExpiresAt`、`reply` を受け取り、本文・履歴・署名を一組で保持する。
2. `POST /api/chat` に `{ sessionId, sessionProof, learningContent, history, message }` を送る。今回の入力は `message` だけに入れる。成功時だけ今回の入力と `reply` を履歴に追加し、応答の `sessionProof` に置き換える。失敗や取り消しでは以前の履歴・署名・下書きを維持する。
3. 20往復後は追加送信を止める。残り15分で振り返りを案内し、期限後は新たな送信・保存を止める。期限到達だけを理由に現在の画面の教材・会話を消さない。
4. 学習者の確定発言が1件以上あるとき、`POST /api/summary` に `{ sessionId, sessionProof, learningContent, history }` を送る。終了時の要求を送信前に凍結する。保存が不明な間に会話を再開したり、別の履歴に更新したりしない。
5. `sessionId` が一致し、`saved: true`、検証済みの `summary`、12文字の `viewKey`、`savedAt`、`expiresAt` を受け取れたときだけ保存完了にする。localStorage の未完了状態を消し、閲覧キーを4文字ごとに区切って表示・コピーできるようにする。
6. 後日は `POST /api/history/open` に `{ viewKey }` を送る。教材・履歴・振り返り・期限を表示する。別のキーを試すときは前の記録を消す。キーは URL、localStorage、ログに残さない。

## 失敗・再送

- `503 STORAGE_UNAVAILABLE`、タイムアウト、通信断、成功レスポンスを検証できない場合は、保存結果が不明になり得る。保存済みと表示せず、凍結した同じ本文・履歴・ID・署名を保つ。
- 署名の期限内に同じ終了要求を手動で再送すると、すでに確定した振り返り・日時・同じ閲覧キーが返る。保存後に応答だけ失われた場合も同じ。自動で新しいセッションを作らない。
- `401 INVALID_SESSION` は署名不正または期限切れ。現在の入力を確認できる状態にし、同じ要求の無限再送をしない。
- `409 SESSION_ALREADY_FINISHED` は同じ ID が別内容で終了済み、または削除済み。上書きできない。新しい ID を勝手に付け替えて保存しない。
- `404 HISTORY_NOT_FOUND` は不正・未保存・期限切れ・削除済みを区別せず「記録を開けません」と案内する。
- JSON 以外のエラー、CORS 拒否、基盤側の429も扱う。教材やキーをエラー報告・ログに含めない。

## 確認シナリオ

- 開始 → 対話 → 振り返り保存 → キーで再閲覧。2時間の期限と保存後の期限が別であること。
- 教材下書き・回答下書き・確定会話が再読み込み後も期限内で復元されること。
- 対話の失敗や遅い応答で、履歴と署名が食い違わないこと。連打で重複発言しないこと。
- 保存応答喪失 → 再読み込み → 同じ要求で再試行して、1件・同じキーになること。
- 保存不明の間に戻るときは再試行・キー取得ができなくなることを確認すること。期限後は端末保存だけ消え、画面内の会話は確認できること。
- localStorage の破損・容量不足・使用拒否、期限切れ・異なる版、共有端末の破棄を確認すること。
- 別のキーを入力したときに以前の記録が残らないこと。閲覧キー・保存済み結果が端末の永続領域に残らないこと。

実サービスとの結合、実モデルの品質、Firestore の IAM・ルール・TTL の適用確認は、ローカルの代替を使ったテストとは別に実施する。
