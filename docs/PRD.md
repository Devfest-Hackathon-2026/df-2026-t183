# プロダクト要件（PRD）

## 背景と課題

授業や参考書を一人で読み直していると、読んだ内容に見覚えがあることと、自分で説明できることを区別しにくい。人に説明すると言葉に詰まる箇所に気づけるが、毎回、同じ内容を聞いてくれる相手を見つけるのは難しい。

「Teach Back（日本語名：AIに教える）」は、聞き手の AI に学習者が説明し、返ってきた質問をきっかけに説明を足す Web アプリ。終わったら実際の会話から、説明できた点と次に復習するとよい点を振り返る。

## 対象

- 主対象は、授業・試験・資格などを自習する高校生・大学生。特定の教科には絞らない。
- 典型例は、授業資料を読み終えた大学生が「なぜそうなるのか」を自分で説明できるか確かめたい場面。
- PC・タブレット・スマートフォンのブラウザで、日本語の文字入力を中心に使う。本人が送信・保存できる教材を使う。

## 提供価値

| 学習者がしたいこと | 体験 |
| --- | --- |
| 今読んだところを復習したい | 教材文を貼り付けるか、PDF・TXT から読み取った本文を確認して開始する |
| 説明のどこが曖昧か知りたい | AI の質問に答えて説明を足す。AI は一度に1つ聞く |
| 次に何を見直すか決めたい | 自分で終了を決め、説明できた点と復習する点を読む |
| 後日、学習内容を見直したい | 終了時に発行された12文字の閲覧キーで、別のブラウザから記録を開く |

## MVP の範囲と段階

遅れても提出できるよう、3段階に分けて作る。第1段階だけでもデモ動画を録れる形にする。

| 段階 | 機能 | 目安 |
| --- | --- | --- |
| 第1段階（必須） | ログイン不要のホーム、教材入力（直接入力・UTF-8 の TXT・テキストを抽出できる PDF）、文字の対話、振り返りの表示（保存しない） | 11/8 中 |
| 第2段階 | 学習中の署名、終了時のサーバー保存、閲覧キーの発行、閲覧キーでの再閲覧 | 11/9 の昼まで |
| 第3段階 | 閲覧キーでの記録の削除 | 11/9 中（余裕があれば） |
| 後の候補 | アカウント別の学習一覧、ログイン、プロフィール、ISBN 登録、学習ロードマップ、キャラクター選択、XP・連続記録、クイズ | — |

遅れたときは、第3段階、第2段階の順に外す。第1段階の中でも遅れたら PDF を外し、直接入力と TXT で提出する。担当と日程は [開発ルール](DEVELOPMENT_RULES.md#段階分担日程)。

添付ファイルは対話の材料になる**教材**。ブラウザで読み取った本文を確認・修正してから開始する。スキャン PDF の OCR、図表や数式の画像解析は対象外とし、本文の貼り付けで続けられるようにする。

音声での回答とAIの質問の読み上げは段階別MVPとは独立した任意機能として扱う。ブラウザで録音して文字起こしし、学習者が確認した文字だけを既存の対話APIへ送る。AIの返答は文字で表示し、Cloud Text-to-Speech による読み上げも利用できる。読み上げに失敗しても文字で対話を続けられる。

## 体験の原則

1. AI は知識ゼロの聞き手として、説明の理由・具体例・つながりを短く聞く。教材は質問の手がかりにし、答えや教材の要約を先に教えない。
2. 学習者が「続ける」「振り返る」を決める。AI による採点や理解度のパーセント表示は行わない。
3. 振り返りは学習者の発言に根拠を置き、誤解の可能性と、会話では確認できなかった点を区別する。
4. 通信が止まっても教材・下書き・確定会話をその画面に残す。
5. 画面の流れと部品はチームの Figma 案を参照し、見た目は Android の Material Design 3 に揃える。文言は最小限にし、ボタンや部品の見た目で分かることに説明を添えない。今回動かす部品は [機能要件](FEATURE_REQUIREMENTS.md#figma-と-mvp-の対応) を参照する。
6. 第2段階からは、教材本文・確定会話・振り返りを終了時にサーバーに保存する。未完了の学習（教材・確定会話・署名・回答下書き・自己確認・凍結状態）と開始前の教材下書きだけは、最長2時間の固定期限付き localStorage で保持する。保存成功・明示破棄・期限切れで取り除き、保存済み結果・閲覧キー・音声は永続化しない。保存する項目、期限、削除方法を事前に伝える。閲覧キーを持つ人が記録を開く・削除する権限を持つ。紛失時は再発行できない。

## デモの完了条件

- 第1段階: 直接入力で学習を開始し、複数往復の対話、振り返りまで公開 URL で通す。UTF-8 の TXT とテキストを抽出できる PDF でも同じ流れを確認する。
- 第2段階: 振り返りと保存の後、別ブラウザで閲覧キーを入力して開ける。保存応答を失って再送しても記録が1件で、同じキーが返る。誤ったキーや期限切れのキーでは読めない。
- 「説明できた点」は、短いまとめと、根拠になった本人の発言を並べて示す。説明していない内容が「説明できた点」に出ない。空入力や読めないファイルには修正方法を示し、失敗後の再試行で入力を失わない。
- スマートフォン・タブレット・PC で主要操作ができ、主要フォームのフォーカスとラベルを確認する。装飾やアニメーションの再現は後に回せる。

学習効果を数値で断定せず、試用者から「説明しづらかった点を見つけられたか」「次に復習する項目が分かったか」を聞いて改善する。

## 提出時の制約

- Cloud Run で学習 API を動かし、Gemini を Vertex AI 経由で呼ぶ。採用理由と比較した案は [技術要件](TRD.md) を参照する。
- オンライン会場の提出では、動くアプリを使ってデモ込みのプレゼン動画を録る。プロダクト説明、構成図、素材・ライブラリの出典とライセンス、AI を使った場面と理由も記録する。
- 開発・提出の締切は 2026-11-10 19:00（日本時間）。提出リポジトリと審査用 URL の案内は運営の最新情報に従う。
