# データ設計

保存は第2段階で入れる。第1段階は保存せず、振り返りを画面に返すだけ。段階は [PRD](PRD.md#mvp-の範囲と段階) を参照。

## 保存の境界

| データ | 学習中 | 終了後（第2段階） |
| --- | --- | --- |
| PDF・TXT のファイル本体 | ブラウザ内で一時的に読み取る | アプリから送信・保存しない |
| 教材本文・確定履歴・下書き | ブラウザのメモリで保持。必要な本文・発言は Go API と Vertex AI に送る | 確認した教材本文と確定履歴を Firestore に保存。未送信の下書きは含めない |
| 振り返り・閲覧キー | Go が振り返りを生成し、検証する | 振り返りを保存し、書き込み確定後に閲覧キーを返す。キー自体は保存しない |
| アカウント | ログイン不要 | 閲覧キーで1件ずつ開く。アカウントや横断一覧は作らない |

未完了の学習（教材・確定会話・署名・回答下書き・自己確認・凍結状態）と開始前の教材下書きだけは、最長2時間の固定期限付き localStorage で保持する。保存成功・明示破棄・期限切れで取り除き、保存済み結果・閲覧キー・音声は永続化しない。利用者は閲覧キーを自分で控える。Firestore を直接読むブラウザ用 SDK は使わず、Go API の実行用サービスアカウントを経由する。

## Firestore の構造

| 保存先 | ドキュメント ID | 値 |
| --- | --- | --- |
| `learningSessions/{sessionId}` | 開始時の UUID v4 | 下の学習記録。削除後は本文を持たない削除印に置き換える |
| `viewKeys/{keyHash}` | 正規化した閲覧キーの SHA-256（16進数） | `sessionId` と `expiresAt` だけ。キー自体は入れない |

学習記録はセッション単位の1ドキュメントとし、保存も読み出しも単一の記録として扱う。

| 項目 | 型・用途 |
| --- | --- |
| `schemaVersion` / `state` | 初期バージョンは `1`。`state` は `saved` または `deleted` |
| `learningContent` / `history` / `summary` | 正規化後の教材本文、順序付き確定履歴、検証済みの振り返り（`understood` の `point`・`evidence`、`review` の `kind`・`text`） |
| `payloadDigest` | 正規化後の教材と順序付き履歴の SHA-256。同じセッションの再送が同内容かを判定する |
| `savedAt` / `expiresAt` | 保存日時と閲覧期限。UTC の Firestore Timestamp |
| `proofExpiresAt` | その学習セッションの署名の期限。削除後の再作成を防ぐために使う |
| `viewKeyId` / `viewKeyNonce` | 閲覧キーを作った鍵の ID と、重なったときに増やす番号 `n`（通常0）。再送時に同じキーを作り直すために使う。秘密値は Secret Manager に置く |

本文、履歴、振り返り、ダイジェストを検索しない。初回のインデックスと TTL の設定は [マイグレーション](MIGRATIONS.md) を参照。

## 確定・再送・削除

1. `/api/summary` は署名と期限を検証し、同じ ID を読む。`saved` かつ内容のダイジェストが同じなら、保存済みの値と `viewKeyId`・`viewKeyNonce` から応答とキーを作り直す。別内容・削除印は409。期限切れの学習署名からは新規保存も再送もできない。
2. 記録がなければ Gemini を呼ぶ。Gemini の呼び出しは、再実行され得る Firestore トランザクションの外で行う。
3. 確定処理では Firestore トランザクション内で再度読み、サーバーの現在時刻で学習署名の期限も確認する。閲覧キーを作り、`viewKeys/{keyHash}` が無いことを確かめる。別のセッションが使っていたら `viewKeyNonce` を1つ増やして作り直す。未作成の場合だけ、学習記録と `viewKeys` の2件を同じトランザクションで作る。競合した場合は先に確定した結果を採用し、同じ内容なら同じ応答、別内容・削除印なら409。並行リクエストで Gemini が複数回呼ばれることはあり得るが、記録は1件に限る。 [Firestore Go のトランザクション](https://docs.cloud.google.com/go/docs/reference/cloud.google.com/go/firestore/latest#hdr-Transactions)
4. 書き込み確定後にだけ閲覧キーを返す。タイムアウト等でコミット結果が分からない場合は503を返す。再送時に既存の確定記録があれば、生成をせず同じ結果とキーを返す。
5. 再閲覧では、受け取ったキーを正規化して SHA-256 を計算し、`viewKeys/{keyHash}` から `sessionId` を引く。学習記録の `state`・期限を確認し、記録の `viewKeyId`・`viewKeyNonce` から作り直したキーが入力と一致することも確かめる。
6. 削除（第3段階）では、キーと記録を検証し、トランザクションで学習データとダイジェストを消去し、`viewKeys` のドキュメントも消す。同じ ID に `state: deleted` と形式版、`expiresAt`（元の `proofExpiresAt`）だけを残す。TTL による削除印の消去は署名が無効になった後。削除済みのレコードは再閲覧できず、古い終了リクエストからも復活しない。

## 鍵と保存期間

- 学習中の署名鍵と閲覧キー用の鍵は別に用意し、32バイト以上の暗号学的乱数を使う。鍵 ID は英数字・ハイフン・アンダースコアの1〜32文字。秘密は Cloud Run の実行側だけに渡す。インスタンス間で共有し、環境をまたいで再利用しない。
- 閲覧キーの形式と作り方は [API 設計](API_DESIGN.md#閲覧キー第2段階) を参照。旧鍵は対応する署名・記録の期限まで検証に使えるようにし、ロールバック時も有効な鍵を消さない。認証情報・キー・教材・モデルの生出力はログに含めない。
- 閲覧期限は保存から30日を初期値とする。`HISTORY_TTL_DAYS` で運用値を指定し、変更は新規記録に適用する。画面は受け取った `expiresAt` を表示し、保存前の案内には当該環境の期間を表示する。公開前に設定と案内の一致を確認する。
- アプリは期限到達時から閲覧を拒否する。Firestore の TTL は物理消去のために使い、即時消去の保証には使わない。学習データを副コレクションや別ストレージへ複製しない。 [Firestore の TTL](https://docs.cloud.google.com/firestore/native/docs/ttl)
