# コーディング規約

## 共通

| 対象 | 規約 |
| --- | --- |
| 仕様書・利用者に見える文章 | 日本語で書き、画面・API・資料で同じ機能名を使う |
| JSON | camelCase。`sessionId`、`learningContent`、`history`、`message`、`reply` などは [API 設計](API_DESIGN.md) の綴りを使う |
| ロールとエラーコード | ロールは `user` / `model`、エラーコードは `UPPER_SNAKE_CASE`。画面に出す日本語と処理に使うコードを分ける |
| 設定 | 環境変数は `UPPER_SNAKE_CASE`。必須設定は起動時またはビルド時に検証する |
| テスト用の素材 | 自作または使用許可を確認した短い教材を使う。教材名や発言に実データを入れない |

## Go

- `gofmt` に従う。パッケージ名は短い小文字、公開する型・関数は必要なものに限る。エラーは呼び出し元で原因を区別できるようにし、HTTP 用の応答への変換はハンドラー側で行う。
- JSON のリクエスト・レスポンスと Gemini SDK の型を分ける。API の項目名は構造体の JSON タグで固定する。
- `context.Context` を HTTP リクエストから SDK に伝える。本文の上限をデコード前に適用し、Gemini や Firestore のタイムアウトと入力上限超過を区別する。
- `go test ./...` で実行できるテストは、デフォルトでネットワークや Cloud の資格情報を要求しない。

## TypeScript と画面

- TypeScript を採用する場合は `strict` を有効にする。ネットワークから得た値は `unknown` から検証し、型アサーションだけで成功にしない。
- コンポーネントは `PascalCase`、関数・変数は `camelCase`。学習セッションの確定履歴と入力下書きを別に扱い、画面をまたいで二重に状態を持たない。
- 読み込み、空、成功、エラーを状態で表す。ボタン・フォーム・リストには標準の HTML 要素を使い、ラベル、フォーカス、通知を組み合わせる。
- 画面の色や文字サイズは共通の変数にまとめる。スマートフォン縦画面から確認し、長いファイル名や応答を折り返す。
- 文字数の数え方は [API 設計](API_DESIGN.md#入力上限) に揃える。JavaScript の文字列長と Unicode コードポイント数が異なる場合にも、API 側の検証結果を優先して表示する。

## AI とデータ

- Gemini の指示は、開始・対話・振り返りごとに一箇所で管理する。変更時は、答えを先に出す・一度に複数質問する・AI の発言を学習者の成果にする、といった崩れがないか例を用いて確認する。
- 教材・モデル出力はプレーンテキストとして扱う。ログやエラーに入力全文、モデルの生出力、認証情報を入れない。
- 学習中の署名、閲覧キー、学習データはログ・URL・分析イベントへ渡さない。未完了の学習（教材・確定会話・署名・回答下書き・自己確認・凍結状態）と開始前の教材下書きだけは、最長2時間の固定期限付き localStorage で保持する。保存成功・明示破棄・期限切れで取り除き、保存済み結果・閲覧キー・音声は永続化しない。実行環境をまたいで秘密鍵を使い回さない。
- 新しい依存を入れる際は、標準機能で足りるか確認し、追加理由・バージョン・ライセンスを残す。
