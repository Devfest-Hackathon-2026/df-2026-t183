# 音声文字起こし API の実装要件

## 目的と採用方式

学習者がマイクへ話した回答を文字へ変換し、内容を確認・修正してからAIとの対話に使用できるようにする。

音声入力には次の方式を採用する。

1. ブラウザで音声を録音する。
2. 音声文字起こしAPIで音声を文字へ変換する。
3. 学習者が文字起こし結果を確認・修正する。
4. 確定した文字を既存の `POST /api/chat` へ送る。

録音した音声をGeminiへ直接送って質問生成まで行う方式は採用しない。文字起こしと質問生成を分けることで、学習者が誤認識を修正でき、既存のテキスト入力と同じ `/api/chat` の契約、会話履歴、入力検証を利用できる。AIの返答は従来どおり文字で表示する。

この機能はMVP第1〜第3段階とは独立した追加機能で、学習中の回答方法として任意に使える。既存の `POST /api/start`、`POST /api/chat`、`POST /api/summary` の入出力は変更しない。

音声バイナリの契約、上限、エラーの正本は [API設計](API_DESIGN.md#音声文字起こし--post-apispeechtranscribe) に定める。本書は画面・実装・検証の要件であり、仕様の追加は本番で音声入力が利用可能になったことを意味しない。

## 処理の流れ

1. 学習者が対話画面で録音を開始する。
2. ブラウザがマイクの利用許可を取得し、対応形式で録音し、30秒を目安に自動停止を要求する。
3. フロントエンドが音声バイナリを `POST /api/speech/transcribe` へ送る。
4. Go APIがメソッド、CORS、`Content-Type`、本文サイズ、音声形式、録音時間を検証する。
5. 検証済み音声をGoogle Cloud Speech-to-Textへ送り、日本語の文字起こしを取得する。
6. Go APIが文字起こし結果を検証し、JSONでフロントエンドへ返す。
7. フロントエンドが結果を編集可能な回答欄へ表示する。
8. 学習者が内容を確認・修正して送信操作をしたとき、文字列を既存の `/api/chat` の `message` として送る。
9. `/api/chat` が成功したときだけ、学習者の回答とAIの質問を確定済み会話履歴へ追加する。

文字起こし成功だけでは `/api/chat` を呼ばず、会話履歴も更新しない。録音音声をGeminiへ渡さず、音声から質問を直接生成しない。

## APIの責務

### 音声文字起こしAPIが行うこと

- 短い音声バイナリを受け取る
- 音声形式、容量、録音時間を検証する
- Speech-to-Textを呼び出す
- 検証済みの文字列を返す
- 失敗時に所定のJSONエラーを返す

### 音声文字起こしAPIが行わないこと

- Geminiへの質問生成
- 教材や会話履歴の受け取り
- `sessionId`、`sessionProof` の検証・更新
- 会話履歴や音声のFirestore保存
- 文字起こし結果の自動送信
- 文字起こし結果のGeminiによる修正・要約

## 入出力

リクエスト：

```http
POST /api/speech/transcribe
Content-Type: audio/webm; codecs=opus

<音声バイナリ>
```

ブラウザが実際に生成したメディアタイプを `Content-Type` に設定する。パラメータ付きの値は `mime.ParseMediaType` 相当で解釈し、次の組み合わせだけを受け付ける。

| `Content-Type` | コンテナ・コーデック |
| --- | --- |
| `audio/webm` | WebM・Opus |
| `audio/ogg` | Ogg・Opus |
| `audio/mp4` | MP4・AAC |

`Content-Type` の申告だけを信用せず、実際のコンテナとコーデックが一致することを検証する。Base64を入れたJSON、`multipart/form-data`、音声ファイル名、クライアントが指定する認識言語・モデルは受け付けない。

成功時（HTTP 200）：

```json
{
  "text": "複数の値を順番にまとめたものです。"
}
```

- `text` はSpeech-to-Textの最終結果を発話順に結合し、前後のUnicode空白を除いた文字列とする。
- 句読点の自動付与を有効にするが、認識結果の意味は書き換えない。
- 複数候補、信頼度、単語ごとの時刻、外部APIの内部IDは返さない。
- 応答は `application/json; charset=utf-8`、`Cache-Control: no-store` とする。

## 上限とタイムアウト

| 対象 | 上限 |
| --- | --- |
| ブラウザの録音 | 30秒を目安に自動停止を要求する |
| APIが受け付ける実音声の長さ | 31秒以下（停止処理・エンコードの遅れのための1秒を含む） |
| HTTP本文 | 5 MiB（5,242,880バイト） |
| 文字起こし結果 | 前後の空白を除いたUnicodeコードポイントで1,000文字 |
| Speech-to-Textの待ち時間 | 最大45秒。API全体の残り時間が短ければ、その時間まで |
| API全体 | リクエストを受けてから最大50秒（本文読み取り・音声検証を含む） |
| フロントエンドの待ち時間 | 送信開始から最大55秒 |
| 1インスタンスの音声処理 | 同時に2件まで。超過時は503で再試行を案内 |

上限を超えた音声や文字列は黙って切り詰めない。本文は `Content-Length` だけを信用せず、上限超過を検出するための1バイト以外は5 MiBを超えて読み込まない。音声データから実際の長さを外部APIの呼び出し前に検証する。長さ情報のないコンテナも音声フレームから安全に時間を判定できれば受け付け、判定不能な破損音声は400とする。

復号した全チャンネルの浮動小数PCMがすべてゼロの完全無音は、外部APIを呼ばず400とする。モノラル化や16bit整数への変換による相殺・丸めを無音判定に使わず、音量のしきい値で小さな声を拒否しない。Speech-to-Textが完全無音にも文字を返す場合への対策であり、雑音や非音声の誤認識まで防ぐものではないため、結果の確認・修正と明示送信を引き続き必要とする。

`MediaRecorder.stop()` とタイマーは非同期なので、画面の30秒とAPIの31秒を区別する。1秒は停止・エンコードの遅れへの猶予であり、APIの31秒にさらに猶予を足さない。バックグラウンド化等で実音声が31秒を超えた場合は413で録り直しを案内し、下書きを残す。通常の停止では、完了まで新しい録音を始めず、最後の `dataavailable` と `stop` を待ってから送る。取消し後の再録音では、旧録音のトラックを停止し、旧イベントが新録音のデータや状態に触れないよう隔離する。

## Speech-to-Textの呼び出し

- Google Cloud Speech-to-Text V2の同期認識を使用し、音声バイト列をインラインで送る。
- 認識言語は `ja-JP`、候補は最良の1件とし、句読点の自動付与を有効にする。
- モデル、Recognizer、認識ロケーションはバックエンド設定で固定し、ブラウザから選ばせない。
- Goクライアントをインターフェースの後ろに置き、実サービスを呼ばない代替実装をテストで注入できるようにする。
- リクエストのキャンセルを外部APIへ伝播し、タイムアウト後の処理を継続しない。
- Cloud Runの実行用サービスアカウントへ必要最小限の認識権限をIAMで付与する。APIキーやサービスアカウント鍵をフロントエンドへ渡さない。
- 音声をCloud Storageへ置かず、文字起こしAPIの処理中だけメモリに保持する。

## フロントエンドの状態と操作

- `MediaRecorder.isTypeSupported` で録音可能な形式を選ぶ。対応形式がない場合は音声入力を無効にし、手入力を案内する。
- 録音前に、マイクを使用することと、文字起こしのため音声をGoogle Cloudへ送ることを伝える。
- 「録音待ち」「録音中」「変換中」「確認・修正」「失敗」を色だけでなく文字でも表示する。
- 録音中は経過時間と停止・キャンセル操作を表示し、録音や変換の二重開始を防ぐ。
- 文字起こし結果を編集可能な回答欄へ表示する。既存の下書きがある場合は、置き換えまたは追加を学習者に選ばせる。
- 学習者が送信操作をするまで `/api/chat` を呼ばない。音声入力を開始したことや文字起こしが成功したことを送信操作として扱わない。
- 文字起こし失敗時は既存の下書きを維持し、録り直しまたは手入力を選べるようにする。自動再送しない。
- マイク利用を拒否した場合も、テキスト入力で学習を続けられる。
- 成功、失敗、キャンセル、画面離脱時にマイクを停止し、不要な音声データをメモリから破棄する。

## 会話履歴とFirestoreとの関係

- 学習中の教材と確定済み会話履歴は、既存仕様どおりフロントエンドのメモリで一時保持し、`/api/chat` を呼ぶたびに送る。
- 音声文字起こしAPIは `sessionId` を必要とせず、音声や文字起こしをFirestoreへ保存しない。
- 第1段階の `/api/summary` は振り返りを返すだけで保存しない。第2段階から、学習終了時に教材・署名済みの確定履歴・振り返りをFirestoreへ保存する。送信済みの文字起こしは通常の学習者発言としてこの対象になる。
- フロントエンドからFirestoreを直接操作しない。Cloud RunのサービスアカウントとIAMでFirestoreへのアクセスを管理し、データベース用のAPIキーやサービスアカウント鍵をブラウザへ渡さない。
- 音声と未確認の文字起こしは `localStorage`、`sessionStorage`、IndexedDB、Cache APIへ保存しない。利用者が確認して回答欄へ取り込んだ文字は回答下書きとして扱い、第2段階の教材・確定会話・署名とともに最長2時間の固定期限付き localStorage で復元できる。保存成功・明示破棄・期限切れで取り除く。

## エラー

エラーは既存APIと同じJSON構造で返す。音声、文字起こし、外部APIの生応答、認証情報、内部設定を含めない。

```json
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "音声を確認して、もう一度録音してください。"
  }
}
```

| 条件 | HTTP | `code` |
| --- | --- | --- |
| 本文なし、壊れた音声、申告形式と実データの不一致、正常な認識応答だが発話なし | 400 | `INVALID_INPUT` |
| ブラウザの許可外オリジンまたは不正なCORSプリフライト | 403 | `ORIGIN_NOT_ALLOWED` |
| POSTと許可済みOPTIONS以外のメソッド | 405 | `METHOD_NOT_ALLOWED` |
| 5 MiBまたは実音声31秒の超過 | 413 | `INPUT_TOO_LARGE` |
| 欠落・不正・未対応の `Content-Type` | 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 認証・IAM・サーバー設定の不備、予期しない内部エラー | 500 | `INTERNAL_ERROR` |
| 下記以外の認識呼び出し失敗、壊れた外部応答、結果の文字数超過 | 502 | `TRANSCRIPTION_FAILED` |
| Speech-to-Textの一時障害・割り当て超過 | 503 | `TRANSCRIPTION_UNAVAILABLE` |
| 音声処理の期限超過 | 504 | `TRANSCRIPTION_TIMEOUT` |

成功した認識応答で `results` が省略または空配列の場合、あるいは正しい文字列を結合して前後のUnicode空白を除くと空になる場合は、発話なしとして400にする。0バイト本文、不正なJSON・UTF-8、オブジェクト以外、`results` の型違い、候補欠落、最良候補の `transcript` 欠落・型違いは502にする。構造を先に検証し、「発話なし」と「壊れた応答」を混同しない。判定の正本は [API設計](API_DESIGN.md#音声固有のエラー) に従う。

許可済みのCORSプリフライトでは、許可メソッドに `POST`、許可ヘッダーに `Content-Type` を設定して204を返す。音声を読み取らず、Speech-to-Textを呼ばない。

## データ保護

- 音声と未確認の文字起こしを、ログ、URL、分析イベント、Firestore、Cloud Storage、ブラウザの永続領域へ保存しない。送信済みの文字は既存の確定会話履歴の契約に従う。
- 音声はブラウザとAPIのメモリ内だけで一時保持し、処理完了、失敗、キャンセル、画面離脱で破棄する。
- 未確認の文字起こしプレビューはメモリだけで保持する。利用者が確認して回答欄へ取り込んだ文字は回答下書きとして第2段階の固定期限付き一時保存に従い、送信後は確定会話履歴の扱いに従う。
- ログにはHTTPステータス、処理時間、バイト数など、音声や発言内容を含まない値だけを記録できる。
- 公開前にGoogle Cloud側のデータ取り扱いと保存設定を確認し、画面の案内と一致させる。

## 作業内容

- `POST /api/speech/transcribe` で音声バイナリを受け取る
- メソッド、CORS、メディアタイプ、本文サイズ、音声形式、録音時間を検証する
- Google Cloud Speech-to-Text V2へ音声を送り、日本語の文字起こしを取得する
- 文字起こし結果が空でなく、1,000文字以内であることを検証する
- 検証済みの文字列をJSONで返す
- 外部APIの失敗、一時障害、タイムアウトを区別してエラーを返す
- Cloud Runのサービスアカウントへ必要なIAM権限を設定する
- フロントエンドへ録音、停止、キャンセル、変換、確認・修正の状態を実装する
- 文字起こし結果を既存の回答欄へ入れ、学習者の送信操作で `/api/chat` を呼ぶ
- バックエンドREADMEへ必要なAPI、IAM、設定、起動方法、バイナリ送信例を記載する

## 完了条件

- 対応ブラウザで日本語音声を録音すると、内容に沿った文字が回答欄へ表示される。
- 学習者が文字起こし結果を修正でき、確認後に既存の `/api/chat` へ文字として送信できる。
- 文字起こしだけでは `/api/chat` が呼ばれず、会話履歴が確定しない。
- 録音音声がGeminiへ直接送信されず、AIの返答が文字で表示される。
- 音声文字起こしAPIがセッション管理やFirestore保存を行わない。
- マイク拒否、無音、破損、未対応形式、上限超過、外部APIの失敗・タイムアウトでもサーバーが停止しない。
- 失敗時に既存の下書きを失わず、録り直しまたは手入力へ戻れる。
- 音声、未確認の文字起こし、認証情報がログ、URL、DB、ブラウザの永続領域に残らない。送信済み文字の第2段階での保存は既存の確定履歴と同じ扱いになる。
- 音声入力を追加しても、既存の開始・対話・振り返りAPIをテキスト入力で引き続き利用できる。

## 敵対的検証の観点

| ケース | 期待する結果 |
| --- | --- |
| 本文なし、0バイト、途中で切れた音声、ランダムなバイト列 | 400。Speech-to-Textを呼ばない |
| WebM/Opus・Ogg/Opus・MP4/AACの完全無音、小さな非ゼロ信号 | 完全無音は外部APIを呼ばず400。小さい音量だけでは拒否しない |
| `audio/webm` を名乗るMP4、許可外コーデック、不正なメディアタイプ | 400または415。申告だけを信用しない |
| 5 MiBちょうどと1バイト超過、実音声30秒・30.5秒・31秒・31秒超 | 容量・時間とも上限内だけ受け付け、超過は外部APIの呼び出し前に413 |
| 30秒の自動停止、最後の音声チャンクの遅延、タブのバックグラウンド化 | 停止完了後の音声を判定する。31秒以内は受け付け、超過は録り直しを案内。二重録音せず下書きを保つ |
| `Content-Length` なしの分割送信、偽の小さい `Content-Length` | 実際に読み取ったバイト数で制限し、無制限にメモリを確保しない |
| 正常な成功応答の `results` 省略・空配列・Unicode空白だけの文字列 | 発話なしとして400。空文字の成功を返さず、録り直しや手入力へ戻れる |
| 成功ステータスだが0バイト本文、不正JSON、型違い、候補・transcriptの欠落 | 502。発話なしの400と区別し、壊れた応答を成功扱いしない |
| 日本語、固有名詞、英数字を含む日本語、複数の認識区間 | 最終結果を発話順に返し、意味を勝手に補正しない |
| 1,000文字と1,001文字、絵文字や改行を含む結果 | 前者は成功、後者は不正な外部応答として502。黙って切り詰めない |
| 認証・IAMの設定不備、不正応答、一時障害、割り当て超過、タイムアウト | 500・502・503・504を区別し、内部情報を漏らさない |
| 変換中のキャンセル、録音・送信の連打、通信失敗後の再試行 | キャンセルを伝播し、二重送信と自動再送を防ぐ |
| 文字起こし前から回答欄に下書きがある | 下書きを黙って上書きせず、置き換えか追加を選べる |
| 文字起こしに「以前の指示を無視して」などが含まれる | 編集可能な文字として表示するだけで自動送信しない |
| 文字起こし成功後に送信せず画面を離れる | `/api/chat` とFirestoreを呼ばず、音声と未確認プレビューを破棄する。回答欄へ採用済みの下書きは、第2段階の期限付き一時保存に従う（明示破棄時は取り除く） |
| 許可外Originと不正なプリフライト | 403。音声を読まず、外部APIを呼ばない |
| 文字起こしの成功・失敗・キャンセル後のログ、DB、ブラウザ保存領域 | 音声と未確認の文字起こしが残らない。送信済み文字は確定履歴の契約に従う |

これらは実装後の確認項目であり、本書の作成時点でSpeech-to-Text APIやブラウザ録音の動作確認が完了したことを示すものではない。

## 対象外

- 音声ファイルをGeminiへ直接送り、質問まで生成する処理
- AIの返答の読み上げ、Text-to-Speech、`POST /api/speech/synthesize`
- 録音中の途中結果、ストリーミング認識、WebSocket、Gemini Live API
- 音声ファイルの保存、再生履歴、ダウンロード
- 文字起こし時のセッション管理、会話履歴の確定、Firestore保存
- ページ再読み込み後の音声・未確認の文字起こしプレビューの復元。回答欄へ採用済み下書きと確定履歴は、第2段階の期限付き復元に従う
- 利用者による認識言語、モデル、複数候補の選択
