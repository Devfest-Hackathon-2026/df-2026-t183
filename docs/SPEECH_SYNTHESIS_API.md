# AI の質問読み上げ API の実装要件

## 目的と位置付け

学習者の回答を文字起こしして送る既存の対話に、AI の質問を音声で聞ける機能を追加する。質問は引き続き画面に文字で表示し、音声再生を使えない場合も学習を続けられるようにする。

これは学習者とAIが交互に話す対話であり、同時に話したり、発話の途中で相手を遮ったりするリアルタイム通話は対象外とする。MVP の3段階とは独立した追加機能で、既存の `/api/start`・`/api/chat`・`/api/summary` の入出力は変更しない。本書は実装要件であり、文書の追加だけで公開環境の読み上げが有効になるわけではない。

## 処理の流れ

1. `/api/start` または `/api/chat` が成功したら、フロントエンドは返された `reply` を質問文として表示し、確定済みの `model` 発言に追加する。
2. フロントエンドがその質問文だけを `POST /api/speech/synthesize` に送る。教材、学習者の回答、履歴、閲覧キーは送らない。
3. Go API が入力を検証し、Cloud Run のサービスアカウントで Cloud Text-to-Speech API を呼び出す。
4. Go API が生成された MP3 をブラウザへ返す。音声ファイルを Firestore や Cloud Storage に保存しない。
5. ブラウザが最新の質問を自動再生する。再生できなければ文字を残し、再生ボタンから利用者が再試行できるようにする。
6. 学習者は既存どおり手入力または録音・文字起こしで回答を作り、確認してから `/api/chat` へ送る。

音声化は対話 API の成功後に行う付加処理とする。音声化の失敗や再生の失敗を、対話 API の失敗として扱わない。読み上げの再試行で `/api/start` や `/api/chat` を呼び直さず、会話履歴を増やさない。

## API 契約

入出力、上限、エラーの正本は [API 設計](API_DESIGN.md#質問の読み上げ--post-apispeechsynthesize) とする。

```http
POST /api/speech/synthesize
Content-Type: application/json

{"text":"配列って、どういうものなの？"}
```

成功は HTTP 200、`Content-Type: audio/mpeg` の MP3 バイナリを返す。`/api/start`・`/api/chat` の `reply` はこれまでどおり文字列であり、音声データをその JSON に埋め込まない。

## 作業内容

### バックエンド

- JSON の `text` だけを受け取り、型、空欄、未知・重複キー、UTF-8、本文サイズ、文字数を外部 API 呼び出し前に検証する。前後の Unicode 空白を除いた文字列を音声化し、元の質問文を変更しない。
- 日本語 `ja-JP`、Chirp 3 HD の `ja-JP-Chirp3-HD-Puck`、MP3 出力をサーバー側で指定する。フロントエンドから声、言語、モデル、SSML を指定させない。
- ゼロは学習者から教わる聞き手として、若々しい男性を意図した `Puck` を使う。専用の男児音声ではないため、声の印象は実際の日本語の質問で確認する。速度・ピッチ加工は加えない。
- Cloud Run に割り当てられたサービスアカウントの認証情報を使う。API キーやサービスアカウントの JSON 鍵をブラウザ、リポジトリ、コンテナイメージに置かない。
- Cloud Text-to-Speech への呼び出し、HTTP 全体、同時処理数、返す音声サイズに上限を設ける。クライアントの切断・キャンセルが起きたら外部呼び出しを中止する。
- API が返した音声の存在・サイズ・MP3 としての妥当性を確認する。空、破損、上限超過の音声を成功として返さない。
- 許可した Origin の CORS と OPTIONS を既存 API に合わせる。成功音声・エラーとも `Cache-Control: no-store` を付け、音声と質問文をログへ書かない。
- 認証・権限の設定不備、一時障害、割り当て超過、期限超過を区別して JSON エラーにする。外部 API の生応答や内部設定は利用者に返さない。

### フロントエンド

- 最初の質問と継続対話の新しい質問の両方を対象に、質問を表示した後で音声を取得する。最新の `model` 発言以外や学習者の回答を自動再生しない。
- 自動再生を基本とし、再生・停止の操作を画面に置く。ブラウザの自動再生制限で `play()` が拒否された場合は、再生ボタンから始められる状態を保つ。
- 新しい質問が来たとき、マイク録音を始めるとき、画面を離れるときは、再生と不要な取得を止める。古いリクエストの完了によって新しい質問の音声が上書きされないようにする。
- 自動再生拒否や再生終了の後は、停止せず保持している音声をメモリ内で再利用できる。停止操作では取得を中止し、音声と Object URL を解放してエラー表示を解除する。停止後の再生は音声を再取得する。音声を `localStorage` やブラウザの永続キャッシュへ置かない。
- HTTP 400・401・404・413・415・429 とキャンセルは日本語で案内する。キャンセル後や古い再生の完了・イベントで、現在の音声とエラー表示を変更しない。
- 音声化が失敗しても質問文・確定済み履歴・回答の下書きを残し、文字で対話を続けられるようにする。再生が遅くても回答欄と送信操作を塞がない。
- 録音中はAI音声を再生しない。録音中に読み上げ完了の応答が届いても、その音声を勝手に再生しない。

### Google Cloud と運用

- Speech-to-Text とは別に、対象プロジェクトで **Cloud Text-to-Speech API** を有効化する。Cloud Run の実行用サービスアカウントが音声合成を呼べることを確認する。ローカルでの動作確認には ADC を使う。
- 課金と利用量を監視し、公開前に Cloud Run の最大インスタンス数・同時処理数・予算アラートを確認する。予算アラートは利用を自動停止する上限ではない。
- 読み上げ API は公開エンドポイントであり、CORS や短い本文の制限だけでは第三者による呼び出しを防げない。既存の [公開 API の守り](TRD.md#公開-api-の守り) に従い、想定外の利用があれば公開範囲またはインスタンス上限を見直す。
- 実装時に `backend/README.md` にローカル起動、Cloud Run の設定、API の呼び出し例を追加する。環境変数を追加する場合は `docs/DEVELOPMENT_RULES.md` と `backend/.env.example` も同じ変更で更新する。

採用する音声と対応地域は [Cloud Text-to-Speech の Chirp 3 HD](https://docs.cloud.google.com/text-to-speech/docs/chirp3-hd) と [対応音声一覧](https://docs.cloud.google.com/text-to-speech/docs/list-voices-and-types) を参照する。料金は [公式料金表](https://cloud.google.com/text-to-speech/pricing) で確認する。

## 完了条件

- 開始時の質問と継続対話で返った新しい質問が、文字で表示されたうえで日本語音声で再生される。
- 自動再生が制限されたブラウザでは、再生ボタンを押せば読み上げられる。停止、再生し直し、次の質問への切り替えができる。
- 録音開始時にAI音声が止まり、AI音声とマイク入力が重ならない。
- 読み上げ API や Cloud Text-to-Speech が失敗しても、質問文と回答欄が残り、文字で学習を続けられる。
- 音声を生成しても、会話履歴の発言数、質問文、署名、保存対象が変わらない。
- 音声、読み上げ用の追加コピー、Google Cloud の認証情報をサーバーログやブラウザの永続領域に残さない。元の質問文と学習署名は第2段階の未完了学習の固定期限付き一時保存に従う。

## 敵対的検証の観点

| 条件 | 期待する動作 |
| --- | --- |
| 空欄、空白だけ、型違い、未知・重複キー、不正な UTF-8、上限超過 | 外部 API を呼ばずに 400 または 413 を返す |
| 許可外 Origin、GET、不正な `Content-Type` | 外部 API を呼ばずに 403、405、415 のいずれかを返す |
| 同時処理上限、Cloud Text-to-Speech の一時障害、期限超過 | 503 または 504 を返し、質問文は画面に残る |
| Cloud Text-to-Speech の空音声、壊れた応答、音声サイズ超過 | MP3 の成功応答にせず 502 を返す |
| 古い質問の音声応答が新しい質問の後に届く | 古い音声を再生せず、新しい質問を表示し続ける |
| 再生中の録音開始、画面離脱、ブラウザの自動再生拒否 | 再生を止め、マイクに混入させず、必要なら手動再生に切り替える |
| 再生ボタンの連打、ネットワーク切断、読み上げ失敗後の再試行 | 音声が重複再生されず、対話 API を再送しない |
| 公開 API へ第三者が短い任意の文を送る | 技術上の呼び出し可能性を認め、入力・同時処理・Cloud Run の上限で費用を抑える。CORS を認証とみなさない |

この表は実装後に確認する項目であり、文書作成時点で動作確認済みであることを示さない。
